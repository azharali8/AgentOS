# AgentOS

AgentOS is a secure, persistent, recoverable, and observable Agentic AI Operating System runtime. It executes multi-step plans generated by LLMs through a strictly controlled, policy-gated LangGraph execution pipeline with human-in-the-loop approval, state checkpointing, and append-only event auditing.

## Phase Status

### [COMPLETED] Phase 0 — Foundation Remediation
- **Workspace Isolation**: Real repository root discovery with traversal and path-escape validation.
- **Terminal Security**: `shell=False` execution with strict rejection of shell operators (`|`, `&`, `;`, `>`, etc.) and shell wrappers (`cmd.exe`, `powershell.exe`, `bash -c`).
- **Platform-Aware Execution**: Whitelist-based command checking (Windows / POSIX).
- **Execution Limits**: Mandatory output truncation (`MAX_OUTPUT_SIZE`) and timeouts (`TERMINAL_TIMEOUT`).
- **Policy Enforcement**: `SecurityManager` enforcing permission matrices and risk levels (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`).

### [COMPLETED] Phase 1 — Agentic Execution Engine
- **Structured Planning**: Pydantic-validated `Planner` producing typed `PlanStep` sequences.
- **8-Node LangGraph**: `plan` -> `select_tool` -> `security` -> `approval` -> `execute` -> `observe` -> `review` -> `replan`.
- **Human-in-the-Loop Interrupts**: Cryptographic parameter binding preventing approval substitution attacks.
- **Reviewer & Replanner**: Observation review supporting `SUCCESS`, `RETRYABLE`, and `FATAL` verdicts with `MAX_REPLANS` and `MAX_RETRIES_PER_STEP`.
- **MockLLMProvider**: Deterministic mock provider for comprehensive, repeatable test suites.

### [COMPLETED] Phase 2 — Persistent Agent Runtime
- **Relational Storage**: SQLite with SQLAlchemy 2.x and Alembic migrations.
- **Domain Repositories**: `TaskRepository`, `ApprovalRepository`, `ExecutionRepository`, `EventRepository`.
- **Persistent LangGraph Checkpointing**: SQLite-backed `SqliteSaver` preserving graph interrupts across process lifecycles.
- **Startup Recovery**: Introspects incomplete tasks on boot. Preserves `WAITING_APPROVAL`, automatically isolates side-effecting operations as `RECOVERY_REQUIRED`, and resumes safe operations.
- **Tool Idempotency Classification**: Request-level policy evaluation (`SAFE_TO_RETRY`, `UNKNOWN_SIDE_EFFECT`).
- **Cancellation Architecture**: `ExecutionManager` handling graceful subprocess termination and event recording.
- **Idempotency Key**: HTTP header `Idempotency-Key` preventing duplicate execution.
- **API & Observability**: Pagination (`limit`/`offset`), event timelines (`/api/tasks/{task_id}/history`), health (`/health`), readiness (`/ready`), and runtime metrics (`/api/metrics`).

### [COMPLETED] Phase 3 — Codebase Intelligence & Software Engineering Runtime
- **Repository Intelligence**: Bounded repository scanning, language detection, and project/framework identification.
- **Code Tools**: Secure `code.search`, `code.read`, and `code.symbols` tools with workspace-bound access.
- **Git Integration**: Read-only structured `git.diff` tool for change inspection.
- **Patch System**: Validated patch application with policy-gated mutations requiring human approval.
- **Test Runner Tool**: Secure, bounded test execution integrated into the tool registry.

### [COMPLETED] Phase 4 — Autonomous Software Engineering & Debugging Runtime
- **Autonomous Coding Workflow**: Dedicated LangGraph pipeline for end-to-end software engineering tasks.
- **Specialized Agents**: Task classifier, code investigator, debugger, failure analyzer, and result judge.
- **Test Service**: Automated test discovery and execution via the Phase 3 test runner.
- **Debugging Models**: Structured root-cause diagnosis and execution metrics tracking.
- **REST API**: `/api/coding` endpoints for orchestrating autonomous engineering workflows.

### [COMPLETED] Phase 5 — Multi-Agent Collaboration & Advanced Agent Runtime
- **Supervisor Architecture**: Supervisor agent coordinating specialized agents via a compiled multi-agent StateGraph.
- **Agent Registry & Permissions**: Least-privilege per-agent authorization matrix and agent catalog.
- **Parallel Execution**: Task decomposition, file-level conflict detection, and result aggregation.
- **Agent Message Bus**: Structured inter-agent communication with budget and supervision controls.
- **Multi-Tier Memory**: Short-term, conversation, semantic, and project memory layers.
- **REST API**: `/api/multi-agent` endpoints for collaborative task execution.

### [COMPLETED] Phase 6 — Production Platform, Observability & Evaluation Runtime
- **Authentication & RBAC**: API key and JWT-based authentication with role-based access control.
- **Rate Limiting**: Sliding-window request guard for API protection.
- **Structured Observability**: JSON logging, correlation middleware, and centralized secret redaction.
- **Metrics & Evaluation**: Runtime metrics, LLM usage tracking, and a 12-case deterministic benchmark suite.
- **Backup & Recovery**: Database and event backup service for production resilience.
- **Production Dashboard**: Observability REST endpoints and CI pipeline (GitHub Actions).

### [COMPLETED] Phase 7 — Adaptive Intelligence Runtime

- **Historical Intelligence**: Execution history, task history, and failure pattern detection.

## Database Schema (Phase 2)

| Table | Description | Key Indexes |
| :--- | :--- | :--- |
| **`tasks`** | Task state, instruction, steps, status, retry counts, final response, errors. | `status`, `created_at`, `thread_id` |
| **`approvals`** | Human-in-the-loop approval records with SHA-256 argument integrity hash. | `task_id`, `status` |
| **`executions`** | Individual tool call execution records with duration and truncated outputs. | `task_id`, `started_at` |
| **`events`** | Append-only event store capturing the complete chronological timeline. | `task_id`, `timestamp`, `event_type` |
| **`checkpoints`** | LangGraph SQLite checkpoint storage. | Managed by `SqliteSaver` |

## API Endpoints

### Tasks
- `POST /api/agent/run`: Start asynchronous task (supports `Idempotency-Key` header).
- `POST /api/agent/run/sync`: Run task synchronously.
- `GET /api/tasks`: List tasks with pagination (`?limit=20&offset=0`).
- `GET /api/tasks/{task_id}`: Retrieve task status and details.
- `POST /api/tasks/{task_id}/cancel`: Request task cancellation.
- `GET /api/tasks/{task_id}/history`: Retrieve append-only chronological event timeline.

### Approvals
- `GET /api/approvals`: List approvals with pagination (`?limit=20&offset=0`).
- `GET /api/approvals/{approval_id}`: Get specific approval request.
- `POST /api/approvals/{approval_id}/resolve`: Approve or reject pending request (`{"status": "APPROVED"}`).

### System & Health
- `GET /health`: Liveness probe.
- `GET /ready`: Readiness probe verifying DB, config, and provider syntax.
- `GET /api/metrics`: Runtime task, approval, and execution metrics.
- `GET /api/tools`: List registered tools and schemas.
